# 长篇生产可靠性补充设计

日期：2026-09-12。核对基线：`for-review@f5dec620647c9a1690b1caaa9d99c0b38e6c695c`。

本设计落实用户引用的《更新设计实现》审查及四个修复工作包；用户已要求“规划一下，然后开始实现”。它补充三阶段路线图，不替代 smoke20、全新离线 L100 和结局审读，也不宣称旧生产作品已经恢复。

## 1. 义务证据及修复

普通续写和历史修订复用现有 ChapterReviewForm 的语义审阅及共同的证据校验。关键词只能定位文本，不能清账。每个兑现判断绑定 obligation ID、完整兑现条件与主体的指纹、候选及 draft ID、正文 SHA-256、审阅身份、判断、正文引用及位置。引用真实并不证明条件成立；现有审阅必须逐项核对主体、条件、否定、假设、未来承诺和角色说法，不能把客观事实、猜测和计划混淆。没有可支持的判断时保持 unknown。

CanonPreparation 冻结这些证据及依赖；CanonAdmission 在锁内复核义务条件、正文和审阅身份，把正文接纳、义务激活/兑现及来源审计放入同一事务。历史修订保留自己的完整后缀和六维核验，仅复用通用证据部分。接纳后维护不再通过第二套关键词规则清账。已有 resolved 历史不自动重置，旧证据不补造成新证据。

未到期 unknown 继续 active；到期强制义务不得用 unknown 取得已兑现豁免。满足真实条件的提前兑现合法，继续受揭示顺序和未来约束限制。

所有义务阻塞通过现有结构化 gate 结果携带具体义务、缺失条件、证据和允许范围。可重写内容进入现有有限修复；计划问题走已有允许的计划修复；格式/模型/配额失败不伪装成内容错误。无执行器或冻结冲突明确停止。重写、重新路由及候选切换不重置当前修复预算，新候选重新评审与准入。

## 2. 持久续跑

任务最终结果与 `generation-continuation:{parent_task_id}:v1` outbox 意图同事务写入。正常完成、Canon 崩溃恢复完成和等待恢复归到同一应用完成入口；进度回调不能先把任务写成 terminal。完成之后的展示或日志失败不能把已完成任务改成 failed。

消费者复用现有续跑决策，在 Project → GenerationTask 锁顺序下原子检查暂停/取消/删除、维护、目标、容量和既有任务，创建子任务或记录明确终止结论。现有 DecisionEvent 保存确定身份的消费决定；任务表增加可空、全局唯一的 continuation_parent_task_id。一项意图即使重复投递、子任务完成或软删除，也只能有一个子任务或一个既定停止结果。

父任务完成后、意图未消费前允许停止该意图；与消费竞争须串行化，不能返回已暂停却悄悄启动子任务。已有其他运行占用项目时旧意图终止为 superseded。子任务沿用父任务不可变策略快照、版本、run_until_chapter、long_run_mode、isolated；仅子任务身份和批次信息更新。历史 completed 任务不推测补发意图。

## 3. 有效检索及增量投影

一次 Writer 上下文固定 project、book_revision 和第 N−1 章读取基线。整书 revision 用于发现并发变化及缓存失效，不作为每条旧记忆必须等于最新 revision 的条件。基线变化最多重建一次整包，仍变化则明确输入构造失败，不混合不同版本。

向量命中只定位候选来源。章节、commit、candidate/draft 和来源文本指纹批量回 active Canon 验证，再取得正式标题、摘要、片段。未知旧身份及过期命中剔除；检索带 as-of 条件并作有限分页补检，记录拒绝/耗尽信息。索引点以内容和来源版本区分，旧 worker 不能覆盖新点。

知识页及其他进入 Writer 的派生页面须带完整语义依赖指纹；实体字段、当前状态、关联集合、地图、可见性及聚合页实际输入都纳入。缺失或失效来源在排序/限额前剔除。Obsidian 和 LLM-KB 备用读取不能绕过验证；旧页面/文件保留，未验证内容不冒充当前事实。必需事实从当前正式 BookState 补取，可选旧片段缺失不暂停整书。

检查点按 book_revision 与 fencing 表达进度，支持同章修订、chapter 0 世界编辑、事件合并、迟到及重复消费。普通投影用 Canon 提交 revision 区间确定变化章节，只加载变化正文；首次未知基线进入显式重建，不每章全量扫描。历史后缀中新身份但相同 embedding 输入可复用向量。

embedding 缓存身份是实际输入指纹、后端/模型身份、维度和预处理版本，持久缓存跨进程复用。模型同维度变化仍不混用。原 reembed 工具改用 active commit 链，不能选择未接纳的最新 draft。旧版本清理不在本次范围。

## 4. 有效上下文

当前客观事实、人物/读者认知、本章计划变化分别表示。已接纳认知从 N−1 的 CognitionView 明确字段、来源事件和生效时点读取，不把 can_see 默认真当成知道。缺记录是 unknown，不能用作者秘密或阶段结束目标补齐。

必需对象由结构化章计划、任务、场景参与者、义务 subject_refs、约束和地点/关系引用产生。按 ID/唯一别名解析，歧义不随意选人；非实体任务类别不假装缺少人物。必需实体身份、当前状态、相关关系优先保留，剩余预算才补可选 top-K。各 Writer 布局不再次盲截断必需集，人物允许名单完整表达实际允许范围。

修复计划更换人物或地点时，从同一 accepted 基线重新取必需事实，不能只裁剪旧包。实际发送的普通、preview、breakdown、scene、stitch 和 repair 提示均验证认知分离及必需状态。必需内容超软字符预算时删除可选内容并记录超额；不以字符估算冒充模型硬 token 限制。真实 provider input-limit 错误明确分类且不重复发送相同输入。

## 5. 迁移、发布与完成证据

所有 schema 变更采用前向 Alembic 迁移，保留旧行及历史引用。旧回执、旧索引、旧义务不填造有效身份。保持发布冻结、修订完整后缀、5% 存稿、offline 隔离、lease fencing 和现有有限预算。

每个工作包先复现，再实现并跑实际事务/实际请求边界回归，分提交与独立审查。集成后固定源码跑全量测试和源码收敛检查，再沿既有候选资格执行 smoke/L100。模型凭据/配额或环境不能支持长跑时如实记录，不能把工程测试写成文学验收通过。生产同步只能使用已验证完整镜像和向前迁移的既定 150 路径；不把开发修复直接覆盖旧兼容运行时。
