# forwin.book_state

Status: CANON runtime.

`book_state` owns the BookState v6 runtime: GraphDelta ledger, extraction contract, deterministic review gate, compiler, snapshot/replay, and projection. P1 adds the story clock, per-book lexicon, versioned node identity, knowledge events, and narrative snapshots. P2 adds unified chapter-delta extraction, translation and world review. P3 adds world ticks and world–plan conflict resolution through Canon admission. P4a adds beat-sheet plan constraints, feasibility checks and POV writer views. The schema head is `0006_planning_v6` (parent `0005_world_plan_conflicts`, which added `world_plan_conflicts`); `0004` dropped `countdown_ledgers` and `character_state_transitions`.

Rules:

- `BookStateCompiler` is the final GraphDelta canon writer and is constructed only by `CanonAdmissionService`.
- `BookStateReviewGate` must run before new changes enter canon, including the Genesis seed.
- For `source_type="chapter_extraction"` deltas the gate also runs the v6 world checks on the delta's `movements`, `knowledge_tags` and `item_transfers` metadata: time offsets, reachability over the mover's known routes, travel speed within `review.travel_tolerance`, restrained movers, entities dead before the chapter acting (flashbacks exempt), item holders, told sources, and reader reveals against the reveal schedule. Location changes without a movement record (a faction's, say), and all other deltas, keep the patch-based reachability check.
- Accepted chapters enter through `CanonAdmissionService.commit_plan`; world edits use `commit_world_edit`, clamp to the latest canon chapter, and recheck under the project lock. The removed `BookStateDirectCommitService` is not an entry point.
- World, map, cognition, and narrative are always enabled; `canon.book_state_layers` has been removed.
- Obsidian, LLM KB, wiki/export, and debug APIs must be rebuildable projections from BookState or declared integration rows.

Genesis handoff:

- Genesis runs `brief → world → map → story_engine → book_blueprint → world_seed`; the old bootstrap stage was removed. The LLM generates `world_seed`, `forwin/genesis/world_seed.py` validates it deterministically, and validation errors prevent locking. Fallback produces a degraded structural shell with actor entries for every story_engine core_cast / opposition / faction id, without inventing story content.
- story_engine entities have ids (generated defaults `cast-n` / `opp-n` / `faction-n`), structured `relationship_axes` / `long_arcs`, and core_cast `secrets` lists.
- Start-writing materializes arcs, bootstraps the map, commits the seed, then writes arc 1's beat sheet and commits its protections at chapter 0; it creates no chapter plan. Arc `title` / `goal` / `stakes` / `payoff_direction` persist on `arc_plan_versions`. Before each chapter run control activates the next arc when the chapter lies past the active one (`ArcProgressionService`, which writes that arc's beat sheet) and plans the chapter's band when it has no plan row (`BandPlanner.ensure_plan_for_chapter`); an unplannable band pauses the run on its `band_planning` conflict.
- `WorldSeedCommitter` builds chapter-0 GraphDeltas with `source_type="genesis_seed"`, passes them through `BookStateReviewGate`, and calls `CanonAdmissionService.commit_world_seed`. That entry locks the project `FOR NO KEY UPDATE`. Chapter-0 subworld character generation is removed.
- `GenesisMapBootstrapError` / `WorldSeedCommitError` inherit `HandoffStageError` and produce `MAP_GENERATION_FAILED` / `WORLD_SEED_COMMIT_FAILED` records.

P1 state contracts:

- Story time is integer minutes since the book's epoch. `graph_deltas.story_time_start/end` store numeric values; the seed uses the opening minute for both. `story_calendars` stores the calendar, and `format_story_time` formats display text.
- `book_lexicons` stores time-unit aliases, rank ladders, currencies, appellations, generic character refs, travel modes, and news speed. Generic refs consume this lexicon; canon name anchors consume BookState kinship edges with `metadata.appellation`, read as “source's appellation → target.” Map generation derives structure from Genesis without genre keyword inference.
- Node `name`, `aliases`, `profile`, and `is_active` are versioned per chapter in `world_node_states`; `world_nodes` is the latest projection. Narrative data is stored in world snapshots. Compilation into an existing chapter builds on that chapter, preserving its accepted changes.
- `agenda`, `intent`, and `clock` are new node types with v6 value validation. Character fields include `alive_status`, `restraint`, and `travel_mode_ids`; location remains `state.location_id`. Actor state includes `actor_tier`, `next_turn_at`, and `resources`; rule profiles include `hardness`, `statement`, and `checkable`. Social edges support `rival_of`.
- Cognition writes use knowledge events and `knowledge_by_ref`; default visibility follows fact sensitivity. Reader promises are narrative `promise` nodes. `book_reader_promises` and proposal `metadata.reader_promise_patches` are removed.

Map and planning contracts:

- The seed's `location_ref` is a Genesis map id, translated at commit to a database map-node id in `state.location_id`. `reveal_candidates` stays in the frozen Genesis pack; `reveal_schedule.earliest_reveal_chapters` first uses active beat-sheet reader reveal targets, then falls back to those candidates mapped to the current ArcPlanVersion chapter_start, including continuation arcs. Chapter reveal_directives permit the named reveal.
- P2 implements chapter-level story-time spans, time monotonicity / flashback rules, and map `travel_time` conversion to minutes.
- P4a uses Genesis handoff for chapter-zero canon and beat sheets plus just-in-time band planning for chapter production. Band `onstage_refs` identify characters; active subworlds derive from chapter plan locations with a current-POV location fallback.

P2 chapter pipeline:

- `ensure_chapter_delta` runs `ChapterDeltaExtractor` at stage `chapter_delta_extraction` once per candidate body (validation retries allowed, including one retry that names refs outside its input tables), reusing a result in draft review and canon preparation only while both its `body_sha256` and its `plan_fingerprint` (`band_planner.persistence.plan_fingerprint`; empty for a chapter without a plan) still match. Its input carries as-of N−1 `ChapterWorldView` entities, locations and relevant secrets, plus plan goals / obligations / reward targets, intents, calendar units, time aliases and travel modes.
- `ChapterDeltaTranslator` turns `WriterOutput.chapter_delta` into graph deltas with `old_value` / `field_path` on non-create patches, `metadata["movements"]` and item `state.holder_id`. `BookStateReviewGate` v6 checks the translated delta; `WorldConsistencyReviewer` exposes the same checks as the `world_consistency` draft signal and routes errors to repair.
- Structured `plan_fulfillment` evidence judges goals and narrative obligations. Keyword checks, `MapMovementReviewer`, writer-contract / regex fallback extraction, countdown/custody audits and canon_quality's parallel ledgers are deleted. The chapter review form reads BookState and persists quality signals only.
- Start-writing flushes arcs, map, chapter-0 seed and arc-1 beat sheet/protections in one caller-owned transaction. On `HandoffStageError` it rolls back all handoff writes, then flushes only the failure event; successful handoff locks the revision and enters writing.

P3 world-engine boundary:

- Post-Canon runs `("world", "plan", "feedback")`; world runs only `WorldTickService.run`. Its step `result_json` contains `tick_id`, `graph_delta_ids`, `conflict_ids`, `dropped_candidate_ids`, `postponed_candidate_ids`, `warnings`, `skipped_reason`. Reader comments are analyzed before feedback aggregation.
- A tick uses `tick-<commit id>`, the chapter's integer-minute story-time window and a deterministic seed. Disabled, non-latest and already-ticked chapters skip; when `target_total_chapters > 0` and the chapter is at or past it, the tick only settles/releases bound held intents without new world activity, returning `skipped_reason="book_complete"` when no write is needed. Candidates come from intent interactions, clock expiries, onstage bookkeeping (chapter bindings and band planning opportunities), due offstage intents (`WorldAdjudicator`, at most 20 per tick), and `ActorTurnRunner`. Hard rules and per-candidate review gate precede impact/budget and narrative-boundary review; LLM candidates get one retry, with actor feedback sanitized to its view, then `WORLD_TICK_CANDIDATE_DROPPED`. LLM outages skip nodes without failing the tick.
- Adjudication full bodies include only the due intents, their owners/targets and held items/resources, and active co-located actors/items/resources/site_states. Events and non-due intents never get full bodies; the compact index excludes events and settled intents but retains pending intents. Facts include every scoped standing fact and scoped event facts, newest first (`created_at_chapter` descending then id ascending): at most `MAX_ADJUDICATION_EVENT_FACTS = 20` in all. Round by round each due intent first gets its own newest ones, up to its guaranteed share of `MAX_ADJUDICATION_EVENT_FACTS_PER_INTENT = 5`; then come scoped events no intent's own full bodies take part in (such as one a shown node names); spare room then goes round by round to the intents that still have events, so a lone intent shows 20. Allowed values include `ended_status`. The tick asks up to 20 due offstage intents in one call; when they are over the prompt guard together, the call takes intents in order while its prompt stays within the guard (`WorldAdjudicator.fits`, no model call), and an intent that does not fit beside them waits. One over the guard even alone is never asked: it is dropped with `prompt_too_large_deferred` and its `scheduled_at` moves to now + 1, so it is due again at the next tick. A retry whose feedback is over the guard keeps the outcomes the first attempt settled. Unasked intents appear as `adjudication:<intent>` in `postponed_candidate_ids`.
- Actor views keep at most `MAX_ACTOR_AGENDAS = 8` active agendas, ordered by priority descending then id ascending. More than `MAX_AGENDA_CHANGES_PER_TURN = 3` agenda_changes triggers a retry with `too_many_agenda_changes`; the prompt carries `max_agenda_changes_per_actor`. Each turned actor's newest five veto_world resolutions are read with SQL limits; a resolution a historical rewrite superseded (`superseded_by_delta`) is left out there and in the reroll count.
- Major impact includes a faction/organization/group/site_state entering an ended `state.status` (`destroyed`, `dissolved`, `disbanded`, `inactive`), changes to faction/group `leader_id` or site_state `controller_faction_id`, and knows/believes effects giving a hidden/secret/must_not_reveal fact to an observer that did not already hold it. A new hidden fact's `known_by` does not count as a new exposure. `must_exist` also breaks on entry into an ended status. Releasing a protection sets `payload.status = "released"` with old_value/field_path; `until_chapter=0` means open and is not a release.
- One news propagation pass feeds `WorldTickDeltaBuilder`; in-transit news lives in delta `metadata["news_in_transit"]`. The tick and a direct resolution share `unprotected_news`: a delivery an active protection forbids is queued again to arrive at now + 1, the next tick, where it arrives once as a rumour (`heard`), which `must_not_know` permits. A tick ends early with `CanonStaleVersion` when the world snapshot it read changed before an adjudication, actor-turn or Codex phase, and a tick that commits nothing still checks the snapshot, without a lock. The engine never writes reader cognition: the gate rejects it with `world_engine_reader_knowledge`. Non-create patches carry `old_value` and `field_path`.
- Before committing, `RunningStateCheck` (`world_engine/running_state.py`) checks base candidates in order, then each in-tick resolution as a group: hard rules use the running runtime left by earlier acceptances, and the world gate checks the cumulative delta. A base candidate that no longer holds is dropped (`constraint_violation`); a stale resolution is rolled back as a group and escalated to a human (`failure_reason="conflict_stale"`), leaving its conflict open. `CanonAdmissionService.commit_world_tick` accepts only `world_engine` deltas on the latest canon chapter, serializes writers with `FOR NO KEY UPDATE`, and is idempotent by `tick_id`. A quiet tick with no patches and no resolutions takes no project lock; otherwise the lock and P27 snapshot check come just before the commit SAVEPOINT. Intervening canon changes make the step stale and retryable. The engine does not write world/map/cognition/narrative tables directly.
- Historical rewrite replays world_engine deltas (ticks and direct `conflict-<id>` resolves) with CAS. Failed deltas retire and create human `replay_cas` conflicts; dependent tick deltas drop in turn, while a dependent non-tick delta refuses the rewrite. Resolutions carried by a dropped delta are superseded in the rewrite transaction; their conflicts stay `resolved`. Their open obligations become terminal `cancelled` through `NarrativeObligationRepository.cancel_obligation`, with `metadata.cancel_reason`, and leave open lists, budgets and gates. Plan patches are reverted only on `planned`/`failed` ChapterPlans and recorded as `plan_patch_revert`; accepted and other plan statuses are untouched. `FuturePlanPatchMixin.revert_plan_patch` removes the obligation/form-instruction contributions, retaining goals or markers another still-active resolution patch on the same plan contributes (P34). An active patch is applied, not reverted, and referenced by a still-resolved conflict not being superseded. Revert cannot restore old items displaced by the five-item caps. The replay_cas `proposed_change` always contains `superseded_conflict_ids`, `cancelled_obligation_ids` and `reverted_plan_patch_ids`; its summary gives the three counts when any resolution is superseded.
- `world_plan_conflicts` owns held changes, offered options, decider, blocking chapter and decision/result refs. Historical rewrite or critical routes to human; for world_tick, minor routes to auto veto, moderate/major to Codex when `world.conflict_delegate="codex"`, otherwise human. `WorldConflictDelegate` defaults to `models.role_preferences["review.world_conflict"] = ("gpt-6-astra",)`, shares Spark's `run_codex_structured_call` and independent audit transactions, and escalates failures or `amend_plan`. `FORWIN_CODEX_MODELS` declares Codex models.
- Historical rewrite offers only `veto_world`; world_tick protection/milestone/reveal_schedule boundaries offer veto/amend; other conflicts offer veto/amend, plus a single `plot_responds` for a live, unsettled intent with no prior resolved plot response. `accept_with_obligation` remains eligible only at minor/moderate, including after a plot response (R42, FU-R47). Veto marks unsettled intents vetoed and schedules a living actor's reroll only while the actor's `veto_world` resolution count on conflicts detected in the inclusive chapter window `[latest - world.max_rerolls, latest]` is below `world.max_rerolls`. Accept commits a `world_change_response` obligation with deadline `min(latest+6, target)` (`latest` is the latest canon chapter; `target` is `project.target_total_chapters`); plot_responds commits only the intent status patch to held (with old_value), binding the intent and a goal to the next unaccepted plan when available, otherwise recording pending_plan_response; human amend commits, releases broken protections and replans the remaining band. Direct resolution uses `commit_world_tick(tick_id="conflict-<id>")` within one SAVEPOINT covering world changes, plan/obligation effects and conflict closure.
- Direct resolution locks the project row `FOR NO KEY UPDATE` immediately after the conflict row and reads canon and the news queue under that lock, making other canon writers wait. It rechecks the option against current canon with the same running-state checks: hard-rule or gate errors raise `ConflictStale` (HTTP/MCP 409), keeping the conflict open; veto passes this stale-change check. Canon write refusal also returns 409. The resolution context and delta `story_time_start` use the latest chapter's extraction start through the current story minute.
- `plot_responds` and `accept_with_obligation` derive writer-facing goals/progress markers, obligation summary/payoff_test, plan-patch contracts and writer/reviewer injections only from the held change's public event summaries. Without a public event they use `PLOT_RESPONSE_GENERIC_GOAL`; onstage_slip uses `ONSTAGE_SLIP_RESPONSE_GOAL`. The conflict summary never enters those writer texts.
- An open human conflict blocks from `blocks_from_chapter`: progress `paused_for_review`, task `needs_review`, derived reason `world_conflict_pending`. Continue and review-approve with `continue_generation=true` return 409 while blocked. Resolve through the HTTP/MCP conflict surface, reread project/task state, then explicitly continue with no active generation task.
- Deterministic map materialization uses the project/subworld SHA-256 seed and declared edge endpoints; existing maps are not automatically rebuilt. Clock producers expire clocks or advance named intents; form protection keeps only the nearest six positive-time running clocks. Secret clock descriptions and later writer constraints hide labels/ids. Travel uses shared `estimate_travel` and the book's modes/known routes; the cognition graph already includes `false_edges` in path queries.

P4 planning and writer boundaries:

- `arc_beat_sheets` and `band_plans` are versioned plans; stages `plan.arc_beats` and `plan.band` save PromptTrace and LLM DecisionEvents. Genesis arc ranges and the target chapter count stay fixed. The beat sheet retains protagonist_ref, reader_promise and arc_payoff_map; experience reads phase purposes and milestones.
- Only beat sheets produce protections. `CanonAdmissionService.commit_plan_constraints` writes a `plan_constraint` delta at the latest canon chapter (0 at handoff), idempotent by sheet id. A replacement releases old protections in the same delta. Historical rewrite rebases release old_value to the current status and skips missing/already-released targets. Creates retain their intent, but missing referenced nodes/facts raise `HistoricalRewriteInvalid` and abort the rewrite (R20). World-engine deltas follow a separate CAS path: mismatches or dependencies on refs created by dropped ticks retire the delta, create a human `replay_cas` conflict and supersede its resolutions.
- Band planning is just in time, supersedes its prior version, updates eligible planned/failed rows in place and reapplies valid NarrativePlanPatches. Accepted/drafted/needs_review rows stay intact. Legacy rows (null band_plan_id) with draft/candidate history retain their plans; never-drafted legacy planned/failed rows are modernized before writing. Pre-write `ensure_plan_for_chapter` reuses existing band-owned rows, but band-owned planned/failed rows remain eligible for later explicit or automatic replanning even with draft history. Run control directly reuses existing rows before the active arc, including never-drafted legacy rows. Completed arcs never reactivate; degenerate ranges produce no writable chapters and log a warning. Publication checks the caller's expected active band version under lock; stale calls return the winner.
- Feasibility checks onstage availability, map reachability/time, reveal/protection rules, secret propositions in writer text and hard-milestone coverage. Unaddressed exit_state, public clocks and due onstage intents warn. Post-Canon errors trigger bounded replanning; remaining errors and pre-write failures persist human plan_feasibility conflicts. Band failure writes no ChapterPlan and becomes band_planning on failed pre-write retry. Both sources offer only amend_plan; PlanAmender revises the sheet for milestone/exit-state problems, otherwise forces replanning with the user's rationale.
- Pending plot responses require status=resolved, decision.option=plot_responds, `decision_json.pending_plan_response is True` and no result ref prefixed `plan_patch:` (R2). They join open obligations as inputs to the next band; saved plans add response patches and attach `plan_patch:<id>` refs. A plot response holds the intent without committing the proposed physical effects, events or news. After its bound chapter enters canon, fulfilled/disrupted intent_interactions take precedence; otherwise the tick releases held to planned with scheduled_at=now, without replaying the old effects. The final chapter also settles/releases its bound holds. Historical supersession rolls back the hold, retires the pending response and reverts eligible plan bindings under P33; the resolved response still consumes that intent's one offer. Missing future plans alone do not escalate plot_responds/accept_with_obligation. Milestone impact depends on actual state changes, not scheduling; an onstage intent first due in the band's last tick is handed to the next band.
- `ChapterWorldView` filters writer context to POV knowledge, recorded reader knowledge, writer-visible map edges, onstage state/holdings, clocks, allowed reveals and truth-free forbidden topics. Budgets are standard 6000/pulp 4000 chars. Personality uses onstage characters; the view supplies permitted names. WorldDigest and planners retain author knowledge; bindings (how/ref) never render to the writer. Goals carry their actions. The writer projection of `arc_payoff_map` omits revelation layers entirely; their summaries are author-only planning notes, planners retain the full map, and chapter reveals reach the writer only through that chapter's reveal directives in the world view (FU-R48). Writer fields are checked for secret propositions (`writer_text_states_secret`); paraphrases still depend on prompt discipline and the reveal gate.
- Scene locations use view ids or new:<name>; extraction receives scene_location_hints as non-evidence. Extraction entity/location tables and relevant secrets now come from ChapterWorldView; both body hash and plan fingerprint must match for reuse. Independent access rules/team speed/edge multipliers are replaced by per-book travel_modes. Plan separately commits arc activation, beat-sheet work, audit/replanning and next-band preparation before committing step completion and trace outbox. Synchronous raw-artifact errors can fail the current unit/step; retries retain and conditionally reuse earlier committed planning work. Post-commit outbox retries only upload.

- Writer input (R41, FU-R45) excludes raw Genesis world/map overviews, long-arc/story-engine summaries, project premise and `setting_summary`; the Genesis revision-id line stays. The protagonist name comes only from `ChapterWorldView.pov_name` or its `known_entities` entry matching `pov_ref`. Validated `reader_promise`, phase purpose and chapter goals carry the pitch; planners and the LLM reviewer may retain author prose.
- Writer-facing review text (R44, FU-R46) renders fact refs by topic for every gate code, using non-concealed subject names. With no nameable subject, `prompt_core` supplies a neutral label, never the fact id or proposition. The author-facing review API preserves `ChapterReviewIssueInfo.original_result`, including raw message and `fact_propositions`.
- Onstage exclusion (R43) covers the chapter plan's `onstage_refs` and `pov_ref` plus every mover and event participant in its committed extraction delta. Actor turns skip them; tick candidates cannot change their location, `alive_status` or `restraint`, or transfer items to/from their holdings. Knowledge and relation changes remain allowed. A touching offstage intent stays due and gets `profile.requires_onstage=true` through a patch with `old_value`, for band planning to stage and bind; the rejected effects emit `WORLD_TICK_CANDIDATE_DROPPED` with reason `touches_onstage_entity`. Both the chapter gate and tick reject `movement_overlap` when a mover departs before its last arrival; the tick considers committed chapter movements and accumulated tick movements.
- The start-writing handoff is the single documented exception to the rule against holding a project row lock across an LLM call. It holds `FOR NO KEY UPDATE NOWAIT` through the first beat-sheet call to atomically hand off arcs, map, chapter-zero seed and sheet protections. Later beat-sheet/band planning acquires publication locks after model calls.
- Design deviations: `models.role_preferences` is consumed only for `review.world_conflict`. There is no `extract.split_calls`; `ChapterDeltaExtractor` uses unified chapter extraction with validation retries.

P4 (P4a + audit follow-up + P4b) is implemented. Production deployment belongs to the separate Task 14 runbook; source status does not establish the running service's version or P5 acceptance.

- Residual `chapter_extraction` conflicts offer `rewrite_chapter` / human `amend_plan`, keep the draft, and resume it after resolution and an explicit continue. They never use auto routing. Latest-chapter rewrites retire and rerun ticks; obsolete open conflicts become `expired`. Earlier rewrites check vanished refs, dropping dependent ticks or rejecting non-tick dependencies.
- `world_variable` / `world.drift` implement bounded one-step drift; `checkable` evaluates five structural predicate kinds. Offstage adjudication can admit new minor actors under per-tick budgets. Extraction entities, locations and relevant secrets now come from `ChapterWorldView`.
- task contracts, `task_contract_json`, their editor/routes and `planning/contracts.py` are deleted. `narrative_constraints` and its editing paths are deleted; protections come from beat sheets. Plans change through `amend_plan`, replanning and plan patches.
- `CostLedgerReport.chapters` reports per-chapter role calls, tokens, durations and usage provenance (no monetary fee fields), world conflicts and human decisions, checkpoint pause codes, band payload trimming and oversized/repeated intent deferrals. Compatibility cleanup and P5 tuning remain in [DESIGN_STATUS](../../Design-docs/DESIGN_STATUS.md#post-deploy-cleanup).
